# Initial GitHub Milestones

Create only the near-term milestones initially. Later milestones can remain in `docs/ROADMAP.md` until the previous stages are close enough to plan meaningfully.

| Milestone | Goal | Exit criterion |
| --- | --- | --- |
| `0.0.1-internal — Vertical Slice` | Prove the architecture end to end | Create → validate → persist → reopen plus minimal export, backup/restore, tests and build artifact |
| `0.1.0 — Project Catalog` | First practically useful local version | Stable project catalog workflows, restart persistence, basic recovery and usability |
| `0.2.0 — Status & Reviews` | Lightweight project steering | Status/review/blocker information usable without task-management scope creep |
| `0.3.0 — Requirements & References` | Traceability foundation | Requirements and typed external references implemented and tested |
| `0.4.0 — Search & Exchange` | Retrieval and portability | Search/filter plus versioned, validated import/export |
| `0.5.0 — MVP` | Mandatory MVP scope | All mandatory MVP requirements accepted with recovery and quality evidence |

Do not create `1.0` issues during the initial bootstrap unless they represent a genuine cross-cutting constraint. Otherwise the backlog becomes a speculative wish list.
